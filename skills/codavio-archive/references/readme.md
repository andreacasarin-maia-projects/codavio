# README guidance

Treat the project README as the default user-facing entry point: a brief introduction for
everyone, followed by practical guidance for the intended users, including technical users and
maintainers. Create it when missing and keep it aligned with supported behavior. Follow project
conventions and audience needs rather than imposing a fixed template.

- Explain what the project does and why it is useful, then prioritize the shortest path to a
  first working result: prerequisites, installation or setup, and a representative usage example
  with its expected outcome. Make using the project distinct from developing it.
- Keep everyday usage easy to revisit. Provide a compact reference for the main commands or
  operations and essential options when applicable, grounded in implementation evidence.
- Make the page easy to scan with descriptive headings, short paragraphs, copyable examples,
  and focused lists or tables. Use screenshots or simple diagrams when they clarify the product
  or a workflow; give images meaningful alternative text. Favor useful presentation over decoration.
- Keep detailed developer instructions and reference material in linked documentation, and
  development decisions and rationale in ADRs. Preserve essential user guidance when shortening.
  Review as a first-time user and a returning user: can they get started and find common tasks?
  Inspect structure, links, and available rendering; report checks that need builder execution.
